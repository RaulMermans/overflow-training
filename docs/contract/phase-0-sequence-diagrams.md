> **Status:** Draft · 2026-03-03

## Flow 1 — Build Routine Template

**Actor:** Authenticated user
**Precondition:** Exercise definitions exist with `scope='system'`
**Postcondition:** `routines` row + N `routine_items` rows owned by user

```
User            UI (app/)       src/db/         Supabase Postgres
 │                │              workouts.ts         │
 │  "New Routine" │                │                 │
 │──────────────►│                 │                 │
 │                │ upsertRoutine  │                 │
 │                │───────────────►│                 │
 │                │                │  INSERT routines│
 │                │                │  {user_id, client_uuid, name}
 │                │                │────────────────►│
 │                │                │  ⟵ routines row │
 │                │◄───────────────│                 │
 │                │                │                 │
 │  Add exercise  │                │                 │
 │  (pick from    │                │                 │
 │   system lib)  │                │                 │
 │──────────────►│                 │                 │
 │                │ upsertRoutine  │                 │
 │                │ Item(s)        │                 │
 │                │───────────────►│                 │
 │                │                │  INSERT routine_items
 │                │                │  {routine_id, exercise_id,
 │                │                │   order, sets, reps, rest, notes}
 │                │                │────────────────►│
 │                │                │  ⟵ routine_items │
 │                │◄───────────────│                 │
 │                │                │                 │
 │  (repeat for   │                │                 │
 │   each item)   │                │                 │
```

**Key data invariants checked here:**

- `exercise_id` must be `scope='system'` (RPC-level check at item insert time)
- `client_uuid` generated by client before INSERT
- `routine_items.order` is 1-based, contiguous preferred

## Flow 2 — Schedule Routine on a Date

**Actor:** Authenticated user
**Precondition:** At least one `routines` row owned by user
**Postcondition:** `scheduled_routines` row with `status='scheduled'`, no data copied

```
User            UI (app/)       src/db/         Postgres RPC
 │                │              workouts.ts     schedule_routine()
 │  Pick routine  │                │                 │
 │  + date        │                │                 │
 │──────────────►│                 │                 │
 │                │scheduleRoutine │                 │
 │                │(routineId,     │                 │
 │                │ scheduledDate) │                 │
 │                │───────────────►│                 │
 │                │                │  POST /rpc/     │
 │                │                │  schedule_routine
 │                │                │  {p_routine_id, p_client_uuid,
 │                │                │   p_scheduled_date}
 │                │                │────────────────►│
 │                │                │                 │ validate: routine.user_id = auth.uid()
 │                │                │                 │ validate: exercise_ids in routine are scope='system'
 │                │                │                 │ INSERT scheduled_routines {
 │                │                │                 │   user_id, routine_id, scheduled_date,
 │                │                │                 │   client_uuid, status='scheduled'
 │                │                │                 │ }
 │                │                │  ⟵ {scheduled_routine_id, status}
 │                │◄───────────────│                 │
 │  Shows on      │                │                 │
 │  calendar      │                │                 │
```

**Notes:**

- No snapshot. Only a reference is stored.
- `scheduled_date` sent as ISO-8601 `YYYY-MM-DD` string (user's local date).
- If user schedules the same routine twice on the same day, two rows are created (multiple allowed; see OQ-01).
- RPC validates routine ownership before insert.

## Flow 3 — Start Scheduled Workout (Snapshot)

**Actor:** Authenticated user
**Precondition:** `scheduled_routines` row with `status='scheduled'`
**Postcondition:** `workouts` row (`in_progress`) + N `workout_exercises` rows (immutable snapshot); `scheduled_routines.status='started'`

```
User            UI (app/)       src/db/         Postgres RPC
 │                │              workouts.ts    start_scheduled_workout()
 │  Tap "Start"   │                │                 │
 │  on scheduled  │                │                 │
 │  routine       │                │                 │
 │──────────────►│                 │                 │
 │                │ startScheduled │                 │
 │                │ Workout(       │                 │
 │                │  scheduledId)  │                 │
 │                │───────────────►│                 │
 │                │                │  POST /rpc/     │
 │                │                │  start_scheduled_workout
 │                │                │  {p_scheduled_routine_id,
 │                │                │   p_workout_client_uuid}
 │                │                │────────────────►│
 │                │                │                 │ -- Ownership check
 │                │                │                 │ SELECT sr FROM scheduled_routines
 │                │                │                 │   WHERE id = p_id AND user_id = auth.uid()
 │                │                │                 │   FOR UPDATE
 │                │                │                 │
 │                │                │                 │ -- Idempotency guard
 │                │                │                 │ IF sr.status = 'started' THEN
 │                │                │                 │   RETURN {workout_id: sr.workout_id, ...}
 │                │                │                 │ END IF
 │                │                │                 │
 │                │                │                 │ -- Guard: no other in_progress workout
 │                │                │                 │ IF EXISTS(SELECT 1 FROM workouts
 │                │                │                 │   WHERE user_id = auth.uid()
 │                │                │                 │   AND status = 'in_progress') THEN
 │                │                │                 │   RAISE EXCEPTION 'WORKOUT_ALREADY_IN_PROGRESS'
 │                │                │                 │ END IF
 │                │                │                 │
 │                │                │                 │ -- Create workout header
 │                │                │                 │ INSERT workouts {
 │                │                │                 │   user_id, client_uuid=p_workout_client_uuid,
 │                │                │                 │   scheduled_routine_id=p_id,
 │                │                │                 │   status='in_progress', started_at=now()
 │                │                │                 │ }
 │                │                │                 │
 │                │                │                 │ -- Snapshot: loop routine_items
 │                │                │                 │ FOR EACH item IN (
 │                │                │                 │   SELECT ri.*, ed.tracking_mode
 │                │                │                 │   FROM routine_items ri
 │                │                │                 │   JOIN exercise_definitions ed ON ed.id = ri.exercise_id
 │                │                │                 │   WHERE ri.routine_id = sr.routine_id
 │                │                │                 │   ORDER BY ri.order
 │                │                │                 │ ) LOOP
 │                │                │                 │   INSERT workout_exercises {
 │                │                │                 │     workout_id, exercise_definition_id=item.exercise_id,
 │                │                │                 │     order_index=item.order,
 │                │                │                 │     planned_sets=item.sets,
 │                │                │                 │     planned_reps=item.reps,
 │                │                │                 │     planned_rest_seconds=item.rest,
 │                │                │                 │     notes=item.notes,
 │                │                │                 │     client_uuid=gen_random_uuid()
 │                │                │                 │   }
 │                │                │                 │ END LOOP
 │                │                │                 │
 │                │                │                 │ -- Mark schedule as started
 │                │                │                 │ UPDATE scheduled_routines
 │                │                │                 │   SET status='started', workout_id=new_workout_id
 │                │                │                 │   WHERE id = p_id
 │                │                │                 │
 │                │                │  ⟵ {workout_id, exercises: [{id, exercise_definition_id,
 │                │                │      planned_sets, planned_reps, planned_rest_seconds,
 │                │                │      tracking_mode, order_index, notes}], ...}
 │                │◄───────────────│                 │
 │  Navigate to   │                │                 │
 │  active session│                │                 │
```

**Key properties:**

- Entire flow is one Postgres transaction. Partial failures roll back completely.
- `FOR UPDATE` lock on `scheduled_routines` prevents race conditions.
- Idempotency: second call with same `scheduled_routine_id` returns existing workout without creating duplicates.
- `workout_exercises` rows are immutable after this point (no add/remove exercise in session).

## Flow 4 — Track Sets

**Actor:** Authenticated user
**Precondition:** `workouts` row with `status='in_progress'`; `workout_exercises` rows exist
**Postcondition:** `workout_sets` rows created/updated; eventually workout `status='completed'`

```
User            UI (app/)       src/db/         Supabase Postgres
 │                │              workouts.ts         │
 │  Log set       │                │                 │
 │  (reps, weight)│                │                 │
 │──────────────►│                 │                 │
 │                │ upsertSet({    │                 │
 │                │  workout_      │                 │
 │                │  exercise_id,  │                 │
 │                │  set_index,    │                 │
 │                │  reps, weight})│                 │
 │                │───────────────►│                 │
 │                │                │  INSERT/UPDATE  │
 │                │                │  workout_sets   │
 │                │                │  ON CONFLICT    │
 │                │                │  (client_uuid)  │
 │                │                │  DO UPDATE      │
 │                │                │────────────────►│
 │                │                │  ⟵ set row      │
 │                │◄───────────────│                 │
 │                │                │                 │
 │  Tick "done"   │                │                 │
 │  on a set      │                │                 │
 │──────────────►│                 │                 │
 │                │ updateSet({    │                 │
 │                │  id,           │                 │
 │                │  is_completed: │                 │
 │                │  true})        │                 │
 │                │───────────────►│                 │
 │                │                │  PATCH          │
 │                │                │  workout_sets   │
 │                │                │  ?id=eq.{id}    │
 │                │                │────────────────►│
 │                │                │  ⟵ updated row  │
 │                │◄───────────────│                 │
 │                │                │                 │
 │  "Finish       │                │                 │
 │   Workout"     │                │                 │
 │──────────────►│                 │                 │
 │                │ finishWorkout( │                 │
 │                │  workoutId)    │                 │
 │                │───────────────►│                 │
 │                │                │  PATCH workouts │
 │                │                │  {status:       │
 │                │                │  'completed',   │
 │                │                │   ended_at: now}│
 │                │                │────────────────►│
 │                │                │  ⟵ updated row  │
 │                │◄───────────────│                 │
 │  Navigate to   │                │                 │
 │  summary screen│                │                 │
```

**Key properties:**

- Sets are upserted via `client_uuid` conflict resolution (offline-safe).
- `is_completed` is reversible while workout is `in_progress`.
- `finishWorkout` sets `status='completed'` and `ended_at`. After this, set writes fail RLS checks (policy should enforce in_progress-only mutations — see Open Questions OQ-06).
- No RPC needed for set tracking; PostgREST direct table access is sufficient.

## Error Flows

### E1 — Start with another workout in progress

```
User → UI → startScheduledWorkout()
          → Postgres RPC
          ← RAISE 'WORKOUT_ALREADY_IN_PROGRESS'
          ← HTTP 409 / PostgREST error object
UI → show "Finish your current workout first" dialog
```

### E2 — Start a non-owned scheduled routine

```
User → UI → startScheduledWorkout(othersScheduleId)
          → Postgres RPC
          ← scheduled_routines SELECT returns 0 rows (RLS filtered)
          ← RAISE 'SCHEDULED_ROUTINE_NOT_FOUND'
          ← HTTP 404
```

### E3 — Start already-started schedule (idempotent return)

```
User → UI → startScheduledWorkout(alreadyStartedId)
          → Postgres RPC
          ← status='started' detected → return existing workout data
          ← HTTP 200 with existing workout_id
UI → navigate to existing in-progress workout
```
